# MMO 后端专项审阅插件

## 适用场景
策划案涉及以下内容时自动加载：
- 拍卖行、交易行
- 世界聊天、组队
- 工会战、跨服
- 拍卖、竞拍
- 世界 BOSS
- 实时战斗同步

## 后端必查清单

### 1. 拍卖行/交易行

| 检查点 | 问题 | 建议 |
|--------|------|------|
| 商品上架 | 上架时是否扣留商品？下架是否返还？ | 原子操作：扣商品 → 生成订单 |
| 并发购买 | 多个玩家同时购买同一件商品，是否超卖？ | 使用数据库行锁或 Redis 事务 |
| 价格范围 | 是否有最低/最高价格限制？ | 明确区间，防止利用交易转移资源 |
| 交易税 | 交易税比例？买方付还是卖方付？ | 明确，通常是卖方付，5-10% |
| 交易记录 | 保存多久？是否需要按条件查询？ | 明确存储周期和查询索引 |
| 过期下架 | 上架商品过期后自动下架？是否通知玩家？ | 明确：过期下架 + 邮件通知 |
| 竞拍机制 | 竞拍截止时间到了以什么规则成交？ | 最高价者得，或最后一分钟出价延长 |

### 2. 世界聊天

| 检查点 | 问题 | 建议 |
|--------|------|------|
| 消息广播 | 广播范围：全服、附近、工会？ | 明确每个聊天频道的范围 |
| 敏感词过滤 | 客户端做还是服务端做？ | 服务端必须做最终过滤，客户端可做预过滤 |
| 消息频率 | 每条消息的 CD？同一玩家发言频率？ | 通常 3-5 秒 CD，防刷屏 |
| 消息队列 | 峰值消息量多少？是否有削峰机制？ | 使用消息队列缓冲 |
| 离线消息 | 离线期间的消息是否保存？保存多少条？ | 明确：保存最近 N 条 |
| 表情/语音 | 支持表情/语音吗？语音文件存储在哪里？ | 明确技术方案（对象存储 + CDN） |

### 3. 工会战

| 检查点 | 问题 | 建议 |
|--------|------|------|
| 同时写入 | 多成员同时攻击 BOSS，贡献度计算 | 使用 Redis INCR 原子操作 |
| 状态同步 | 工会战状态（进行中、已结束）同步到所有成员 | 使用推送 + 轮询兜底 |
| BOSS 血量 | BOSS 血量从哪读取？是否有缓存？ | Redis + 定期持久化到 DB |
| 奖励分发 | 战斗结束后如何发奖？批量发还是逐个发？ | 异步队列发放，避免阻塞 |
| 参与判定 | 参战贡献最低要求？未达标的算有效参与吗？ | 明确最低贡献 |

### 4. 组队/副本

| 检查点 | 问题 | 建议 |
|--------|------|------|
| 队伍上限 | 队伍人数上限？ | 通常 4-5 人 |
| 队长转移 | 队长离线后是否自动转移？ | 明确：离线 X 分钟后转移给队内活跃成员 |
| 匹配机制 | 匹配池大小？匹配算法复杂度？ | 明确匹配逻辑 |
| 副本实例 | 每个队伍独立副本还是共享？ | 明确实例隔离规则 |
| 掉线重连 | 战斗中掉线重连能否回到战斗？ | 保留战斗状态 X 分钟，支持重连 |
| 队长分配 | 掉落物品由队长分配还是自动分配？ | 明确分配规则 |

### 5. 跨服

| 检查点 | 问题 | 建议 |
|--------|------|------|
| 数据隔离 | 跨服期间玩家原服数据如何访问？ | 只读 或 复制一份快照 |
| 跨服入口 | 进入跨服是否需要排队？最大容量？ | 明确容量上限 |
| 跨服回调 | 跨服战斗结束后结果如何同步回原服？ | 双服确认机制 + 重试队列 |
| 跨服状态 | 跨服期间原服的聊天/工会是否可用？ | 明确：是否完全隔离 |
| 返回原服 | 跨服结束后返回原服的数据同步 | 增量同步，避免全量 |

### 6. 世界 BOSS

| 检查点 | 问题 | 建议 |
|--------|------|------|
| 参战人数 | 同时参战人数上限？ | 明确，超出则进入排队 |
| 伤害排名 | 排名实时更新还是 BOSS 死后计算？ | 建议定时刷新（每 10 秒） |
| 并发写入 | 多玩家同时写入伤害数据 | Redis Sorted Set 或 Lua 脚本 |
| BOSS 刷新 | 刷新时间？多个服务器共享 BOSS 吗？ | 明确刷新规则 |

### 7. 实时战斗同步

| 检查点 | 问题 | 建议 |
|--------|------|------|
| 同步方式 | 帧同步还是状态同步？ | 明确，对性能影响大 |
| 网络延迟补偿 | 如何处理高延迟玩家的操作？ | 明确方案：预测回滚或延迟补偿 |
| 断线重连 | 战斗中断线重连，能否恢复到当前帧？ | 保存关键帧，支持重放 |
| 反作弊 | 客户端上报操作 vs 服务端全计算 | 关键战斗必须有服务端验证 |

## 输出格式

### 标准输出格式

| 优先级 | 序号 | [MMO]模块 | 问题描述 | 建议补充/修改 |
|--------|------|-----------|----------|----------------|
| P0 | 1 | 拍卖行 | 并发购买无锁，存在超卖风险 | 用数据库行锁 + 乐观锁 |
| P0 | 2 | 工会战 | 多人同时攻击无原子保证 | 使用 Redis INCR |
| P1 | 3 | 世界聊天 | 消息广播范围未定义 | 明确：全服还是分线 |

### 输出要求
- 按优先级排序：P0 → P1 → P2
- 每个问题必须包含：问题描述、建议修改
- 模块必须包含 `[MMO]` 标签

### 无问题输出格式
如果未发现问题，输出：
```
✅ MMO 后端专项检查通过，未发现明显问题

检查模块：
- ✅ 拍卖行/交易行
- ✅ 世界聊天
- ✅ 工会战
- ✅ 组队/副本
- ✅ 跨服
- ✅ 世界 BOSS
- ✅ 实时战斗同步
```

## 异常情况处理

| 异常情况 | 处理方式 |
|----------|----------|
| 策划案为空 | 输出错误："策划案内容为空，请提供有效的策划案内容" |
| 策划案格式异常 | 输出错误："策划案格式异常，请检查文件格式" |
| 不包含MMO内容 | 输出警告："策划案未包含MMO相关内容，检查结果可能不完整" |
| 审阅执行失败 | 输出错误："审阅执行失败，请检查策划案内容或联系技术支持" |

## 边界情况处理

### 策划案内容不完整
- **情况**：策划案只包含部分MMO功能描述
- **处理**：基于现有内容审阅，输出警告提示可能遗漏的检查点

### 跨服架构不明确
- **情况**：策划案未明确跨服的架构设计（数据隔离、状态同步）
- **处理**：在问题描述中标注，建议明确跨服架构，避免后期架构调整困难

### 并发规模不明确
- **情况**：策划案未明确并发规模（同时在线人数、同时参战人数）
- **处理**：在问题描述中标注，建议明确并发规模，以便评估性能和架构需求
