# SLG 后端专项审阅插件

## 适用场景
策划案涉及以下内容时自动加载：
- 行军、部队移动
- 攻打、占领、争夺
- 坐标、大地图、地块
- 联盟、公会
- 攻城战、集结
- 资源田、建筑

## 后端必查清单

### 1. 行军系统

| 检查点 | 问题 | 建议 |
|--------|------|------|
| 队列上限 | 每个玩家的行军队列长度上限？ | 明确上限，通常 3-5 队 |
| 队列冲突 | 同一块土地同时被多队行军时怎么处理？ | 先到先得或按战力判定 |
| 行军取消 | 行军途中是否可以取消？资源是否返还？ | 明确：取消是否返还兵力和资源 |
| 到达时间 | 行军到达时间由客户端还是服务端计算？ | 服务端计算，客户端只做展示，防止改时间作弊 |
| 路径重叠 | 多支部队在路径上相遇怎么办？ | 明确是否发生战斗或互相穿越 |

### 2. 攻打/战斗

| 检查点 | 问题 | 建议 |
|--------|------|------|
| 并发攻打 | 多人同时攻打同一块土地的锁机制？ | 使用分布式锁或乐观锁（版本号） |
| 战斗验证 | 战斗结果由谁计算？ | 必须服务端全量计算，不能信任客户端 |
| 伤兵机制 | 战斗后伤兵比例？治疗消耗？ | 明确公式和资源消耗 |
| 战报存储 | 战报保存多久？永久还是定期清理？ | 建议保留 30 天，超过归档或删除 |
| 战报分发 | 战报推送到哪些人？（攻击方、防守方、联盟成员） | 明确推送范围 |

### 3. 大地图/地块

| 检查点 | 问题 | 建议 |
|--------|------|------|
| 状态机 | 每个地块的状态流转是否有完整定义？ | 空闲→攻打中→占领中→保护中→空闲 |
| 占领规则 | 占领条件？是否需要连接地块？ | 明确连通度规则 |
| 保护时间 | 被占领后是否有保护期？多长？ | 明确，通常是 5-15 分钟 |
| 超级大地图 | 坐标系统用 int 还是 string？总格点数？ | 预估总格点数，int 上限 21 亿是否够用 |
| 地块归属 | 归属于玩家还是联盟？转移规则？ | 明确 |

### 4. 联盟系统

| 检查点 | 问题 | 建议 |
|--------|------|------|
| 联盟上限 | 成员数量上限？ | 明确，通常 50-100 人 |
| 联盟唯一性 | 联盟名称唯一性如何保证？合服后冲突？ | `server_id + guild_name` 联合唯一 |
| 联盟科技 | 科技升级是否需要分布式锁防止并发 | 联盟科技通常多人捐献，需要锁 |
| 联盟帮助 | 一键帮助的实现方式？性能？ | N 个成员帮助同一建筑，需要去重 |
| 联盟战 | 多成员同时攻击 BOSS，贡献计算如何原子化？ | 使用 Redis INCR 或 Lua 脚本 |

### 5. 行军/攻城

| 检查点 | 问题 | 建议 |
|--------|------|------|
| 攻城窗口 | 攻城有开放时间窗口吗？（如 20:00-22:00） | 明确时间范围 |
| 集结机制 | 集结上限多少人？发起人可踢人吗？ | 明确规则 |
| 耐久度 | 城墙耐久度与战斗的映射关系？ | 明确公式 |
| 占领条件 | 耐久度归零后立刻占领还是需要其它条件？ | 明确 |

### 6. 定时器/延迟任务

| 检查点 | 问题 | 建议 |
|--------|------|------|
| 行军到达 | 定时器用什么实现？ | Redis ZSET / 延迟队列 / 轮询扫表 |
| 建造完成 | 类似行军到达，用什么实现？ | 同上，推荐 Redis ZSET |
| 定时器失效 | 服务器重启时定时任务是否会丢失？ | 需要持久化 + 重启后恢复机制 |
| 时间同步 | 服务端时间与客户端时间不一致怎么处理？ | 所有定时器以服务端时间为准 |

### 7. 跨服/合服

| 检查点 | 问题 | 建议 |
|--------|------|------|
| 跨服战斗 | 跨服期间数据隔离规则？ | 跨服服只读，或临时复制数据 |
| 合服冲突 | 玩家同名、联盟同名如何处理？ | 加后缀 + 送改名卡 |
| 合服迁移 | 大地图地块归属如何迁移？ | 需要有完整的合服迁移脚本 |

## 输出格式

### 标准输出格式

本插件输出时，问题前加 `[SLG]` 标签：

| 优先级 | 序号 | 问题类型 | 具体位置 | 问题描述 | 建议补充/修改 |
|--------|------|----------|----------|----------|----------------|
| P0 | 1 | [SLG]并发攻打 | 3.2 攻打规则 | 多人同时攻打无锁方案 | 使用 Redis 分布式锁 |
| P0 | 2 | [SLG]定时器 | 行军到达 | 服务端重启是否会丢失行军任务 | 持久化到 Redis ZSET，重启后恢复 |
| P1 | 3 | [SLG]联盟唯一性 | 联盟创建 | 联盟名称跨服冲突 | 改为 (server_id, name) 联合唯一 |

### 输出要求
- 按优先级排序：P0 → P1 → P2
- 每个问题必须包含：具体位置、问题描述、建议修改
- 问题类型必须包含 `[SLG]` 标签

### 无问题输出格式
如果未发现问题，输出：
```
✅ SLG 后端专项检查通过，未发现明显问题

检查模块：
- ✅ 行军系统
- ✅ 攻打/战斗
- ✅ 大地图/地块
- ✅ 联盟系统
- ✅ 行军/攻城
- ✅ 定时器/延迟任务
- ✅ 跨服/合服
```

## 异常情况处理

| 异常情况 | 处理方式 |
|----------|----------|
| 策划案为空 | 输出错误："策划案内容为空，请提供有效的策划案内容" |
| 策划案格式异常 | 输出错误："策划案格式异常，请检查文件格式" |
| 不包含SLG内容 | 输出警告："策划案未包含SLG相关内容，检查结果可能不完整" |
| 审阅执行失败 | 输出错误："审阅执行失败，请检查策划案内容或联系技术支持" |

## 边界情况处理

### 策划案内容不完整
- **情况**：策划案只包含部分SLG功能描述
- **处理**：基于现有内容审阅，输出警告提示可能遗漏的检查点

### 大地图规模不明确
- **情况**：策划案未明确大地图的规模（格点数量、坐标范围）
- **处理**：在问题描述中标注，建议明确大地图规模，以便评估性能和存储需求

### 跨服/合服规划缺失
- **情况**：策划案未包含跨服或合服的相关规划
- **处理**：在问题描述中标注，建议补充跨服/合服的规划，避免后期架构调整困难
