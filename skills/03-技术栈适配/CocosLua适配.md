# Cocos Lua 技术栈适配

## 适用场景
项目前端使用 Cocos Lua 引擎时，在审阅策划案时追加以下检查点。

## 必查清单

### 1. Lua 内存管理

| 检查点 | 问题 | 建议 |
|--------|------|------|
| 内存泄漏 | table 引用是否及时置 nil？ | 及时释放不再使用的引用 |
| 全局变量 | 是否意外创建了全局变量？ | 变量前加 local |
| 闭包使用 | 闭包中是否持有外部引用导致无法释放？ | 注意循环引用 |
| 对象池 | 频繁创建销毁的 table 是否使用对象池？ | 实现 table 池 |

### 2. 性能优化

| 检查点 | 问题 | 建议 |
|--------|------|------|
| table 操作 | table 的 key 类型？string vs number 性能差异 | 数字 key 更快 |
| 字符串拼接 | 大量字符串是否使用 table.concat？ | 禁止循环内用 .. 拼接 |
| update 调用 | 每帧 update 是否能合并？ | 用定时器代替部分 update |
| 元表使用 | 元表的使用是否过多影响性能？ | 适度使用 |

### 3. 资源管理

| 检查点 | 问题 | 建议 |
|--------|------|------|
| 加载回调 | 异步加载的回调中是否考虑场景切换的情况？ | 加有效性判断 |
| 资源释放 | 资源释放策略？是否需要手动 purge？ | 明确释放时机 |
| 缓存策略 | 是否缓存了 texture 引用导致无法释放？ | 用弱引用表 |

### 4. 代码组织

| 检查点 | 问题 | 建议 |
|--------|------|------|
| 模块拆分 | 代码是否按功能模块拆分（require）？ | 明确模块划分 |
| 命名规范 | 变量/函数命名是否规范？ | 统一命名风格 |
| 错误处理 | xpcall / pcall 使用？错误上报？ | 关键路径加保护 |

### 5. 热更新

| 检查点 | 问题 | 建议 |
|--------|------|------|
| 代码热更 | Lua 代码是否支持热更？ | assetManager 或自研 |
| 版本管理 | 热更版本号管理？ | 明确版本比对方案 |

### 6. 游戏逻辑

| 检查点 | 问题 | 建议 |
|--------|------|------|
| 协程 | 是否使用协程（coroutine）？注意生命周期管理 | 场景切换时清理 |
| 定时器 | scheduler 定时器是否正确取消？ | 场景销毁时清理 |

## 输出格式

| 优先级 | 序号 | [Lua]模块 | 问题描述 | 建议修改 |
|--------|------|-----------|----------|----------|
| P1 | 1 | 内存 | 闭包持有场景引用导致泄漏 | 及时置 nil |
| P1 | 2 | 性能 | 循环内 .. 拼接字符串 | 改用 table.concat |
| P2 | 3 | 代码 | 多处全局变量定义 | 加 local 修饰 |
