# C++ 技术栈适配

## 适用场景
项目后端使用 C++ 语言时，在审阅策划案和设计审查时追加以下检查点。

## 必查清单

### 1. 内存管理

| 检查点 | 问题 | 建议 |
|--------|------|------|
| 智能指针 | 裸指针的使用场景？是否需要智能指针？ | 明确：shared_ptr/unique_ptr 使用规范 |
| 内存泄漏 | 动态分配的内存是否有对应释放？ | 使用 RAII，避免 new/delete 裸露 |
| 循环引用 | shared_ptr 是否可能产生循环引用？ | 使用 weak_ptr 打破 |
| 内存池 | 高频创建的对象是否使用内存池？ | 明确需要池化的对象 |

### 2. 并发与线程

| 检查点 | 问题 | 建议 |
|--------|------|------|
| 数据竞争 | 共享数据是否有锁保护？ | 使用 mutex、读写锁或无锁结构 |
| 死锁风险 | 多个锁的加锁顺序是否一致？ | 明确锁层级 |
| 线程安全 | 类的接口是否线程安全？ | 在文档中明确 |
| 线程数量 | 线程池大小？是否与 CPU 核心数匹配？ | 明确配置 |

### 3. 性能

| 检查点 | 问题 | 建议 |
|--------|------|------|
| 拷贝开销 | 大对象是否按引用传递？ | 使用 const & 传递 |
| 移动语义 | 是否需要实现移动构造/赋值？ | 明确 |
| 内联优化 | 热点函数是否考虑内联？ | 明确 |
| 缓存友好 | 数据结构是否考虑缓存行对齐？ | 高频访问结构需注意 |

### 4. 容器使用

| 检查点 | 问题 | 建议 |
|--------|------|------|
| 容器选择 | vector/list/map/unordered_map 选型是否合理？ | 按访问模式选择 |
| 预留空间 | vector 是否预分配 reserve()？ | 已知大小时必须 |
| 增删模式 | list 是否在中间频繁插入删除？vector 不合适 | 明确 |

### 5. 异常处理

| 检查点 | 问题 | 建议 |
|--------|------|------|
| 异常使用 | 是否使用异常？还是返回错误码？ | 统一规范 |
| 异常安全 | 函数是否保证基本/强异常安全？ | 明确级别 |
| 析构函数 | 析构函数是否可能抛异常？ | 禁止 |

### 6. 编译与构建

| 检查点 | 问题 | 建议 |
|--------|------|------|
| 依赖管理 | 第三方库如何管理？ | 明确：vcpkg/conan/子模块 |
| 编译优化 | 不同环境的编译优化级别？ | Debug vs Release |
| 头文件依赖 | 是否使用前置声明减少依赖？ | 明确 |

### 7. 游戏后端特有

| 检查点 | 问题 | 建议 |
|--------|------|------|
| 网络库 | 使用什么网络库（asio/libuv）？ | 明确 |
| 序列化 | 使用 Protobuf 还是自研？ | 明确 |
| 对象池 | 玩家对象、实体对象是否使用对象池？ | 推荐 |
| 定时器 | 定时器实现方案？ | 时间轮 vs 堆 |

## 输出格式

| 优先级 | 序号 | [C++]模块 | 问题描述 | 建议修改 |

| P2 | 3 | 性能 | vector 未预分配 | 使用 reserve() |
