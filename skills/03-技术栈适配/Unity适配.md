# Unity 技术栈适配

## 适用场景
项目前端使用 Unity 引擎时，在审阅策划案时追加以下检查点。

## 必查清单

### 1. 内存管理

| 检查点 | 问题 | 建议 |
|--------|------|------|
| 对象池 | 频繁实例化和销毁的 GameObject 是否使用对象池？ | 实现 GameObject 池 |
| 资源泄漏 | AssetBundle 加载后是否及时 Unload？ | 明确释放时机 |
| 引用泄漏 | 事件注册是否在 OnDestroy 中取消？ | 规范：注册必有反注册 |
| GC 压力 | 每帧是否产生大量临时对象（结构体装箱）？ | 减少 Update 中的分配 |

### 2. 性能优化

| 检查点 | 问题 | 建议 |
|--------|------|------|
| 组件查找 | 是否频繁使用 GetComponent？是否缓存？ | 在 Awake/Start 中缓存 |
| Update 使用 | 空 Update 函数是否存在？不必要的每帧调用？ | 删除空 Update，改用协程 |
| 视图裁剪 | 是否使用视锥体剔除和遮挡剔除？ | 明确裁剪策略 |
| LOD | 是否考虑 LOD（细节层次）降低远处模型面数？ | 明确 LOD 分组 |
| 物理计算 | 是否合理使用物理层掩码？减少碰撞检测 | 设置正确的 Layer |

### 3. 资源管理

| 检查点 | 问题 | 建议 |
|--------|------|------|
| AB 包 | AssetBundle 的分包策略？ | 按场景/角色/UI 分包 |
| 资源加载 | 异步加载的完成回调是否考虑对象已销毁？ | 加 `this == null` 判断 |
| 图集/纹理 | 纹理的导入设置（格式、大小、mipmap）是否合理？ | 按平台配置 |
| 预加载 | 关键资源的预加载策略？ | 明确预加载时机 |

### 4. UI 系统

| 检查点 | 问题 | 建议 |
|--------|------|------|
| 网格重建 | 频繁变化的 UI（如计时器、血量）是否使用 TextMeshPro？ | TMP 更高效 |
| 射线检测 | 大量 UI 的射线检测是否影响性能？ | 关闭不需要的 RaycastTarget |
| Canvas 拆分 | 不常变的 UI 是否单独 Canvas？ | 减少全屏重建 |
| 布局组件 | Layout Group 是否在频繁变动时禁用？ | 变动完再启用 |

### 5. 网络与同步

| 检查点 | 问题 | 建议 |
|--------|------|------|
| 帧同步 | Unity 的帧同步方案？ | 明确实现方式 |
| 序列化 | 网络消息的序列化方式（Protobuf/Json）？ | 明确 |

### 6. 打包与发布

| 检查点 | 问题 | 建议 |
|--------|------|------|
| 包体大小 | 首包大小控制？可选的资源下载？ | 分包 + 按需下载 |
| 平台差异 | iOS/Android/PC 的差异处理？ | 预处理指令 `#if UNITY_IOS` |
| 热更新 | 代码热更方案？（ILRuntime/HybridCLR） | 明确 |

### 7. 调试与工具

| 检查点 | 问题 | 建议 |
|--------|------|------|
| 日志 | 生产环境是否关闭 Debug.Log？ | 开关控制 |
| 性能分析 | 是否有内置性能开关（显示 FPS、draw call）？ | 内置或不内置，测试用 |

## 输出格式

| 优先级 | 序号 | [Unity]模块 | 问题描述 | 建议修改 |
|--------|------|-------------|----------|----------|
| P1 | 1 | 性能 | 子弹频繁实例化销毁 | 使用对象池 |
| P1 | 2 | UI | 血量数字频繁变化导致网格重建 | 改用 TextMeshPro |
| P2 | 3 | 资源 | AssetBundle 分包策略未定义 | 按场景/角色分包 |
