# Go 技术栈适配

## 适用场景
项目后端使用 Go 语言时，在审阅策划案和设计审查时追加以下检查点。

## 必查清单

### 1. 并发模型（goroutine）

| 检查点 | 问题 | 建议 |
|--------|------|------|
| goroutine 泄漏 | 策划案中的定时任务、长连接处理是否有 goroutine 退出机制？ | 使用 context 控制生命周期 |
| 无界创建 | 批量处理时是否可能创建大量 goroutine？ | 使用 worker pool 限制并发数 |
| 通道阻塞 | 无缓冲通道在发送端和接收端不匹配时可能死锁 | 明确通道方向和使用场景 |

### 2. 内存管理

| 检查点 | 问题 | 建议 |
|--------|------|------|
| 对象复用 | 高频创建的对象（如消息体）是否使用 sync.Pool？ | 明确需要池化的对象 |
| 字符串拼接 | 大量字符串拼接是否使用 strings.Builder？ | 循环内禁止使用 + 拼接 |
| 切片预分配 | 已知大小的切片是否预分配容量？ | make([]T, 0, cap) |
| 指针使用 | 大结构体是否用指针传递？小对象用值传递 | 明确规则 |

### 3. 错误处理

| 检查点 | 问题 | 建议 |
|--------|------|------|
| 错误忽略 | 是否有 `_` 忽略错误的情况？ | 除非明确可忽略，否则必须处理 |
| 错误包装 | 错误返回时是否包含上下文信息？ | 使用 `fmt.Errorf("xxx: %w", err)` |
| panic 使用 | 是否在非初始化阶段使用 panic？ | 明确：业务逻辑禁止 panic |

### 4. 数据库/缓存访问

| 检查点 | 问题 | 建议 |
|--------|------|------|
| 连接池 | 数据库连接池配置是否合理？最大连接数？ | 明确配置 |
| 批量操作 | 批量查询是否使用 IN 而非循环单查？ | 必须批量 |
| 事务长度 | 事务内是否有 RPC 或长循环？ | 事务尽量短 |
| context 传递 | 超时控制是否通过 context 传递？ | 必须 |

### 5. 接口与 API

| 检查点 | 问题 | 建议 |
|--------|------|------|
| 结构体 tag | JSON/DB tag 是否完整？ | 明确命名规范 |
| 字段验证 | 入参验证是否使用 validator 库？ | 明确验证规则 |
| 错误码 | 错误码是否统一使用自定义类型？ | 建议 `type ErrorCode int` |

### 6. 配置与部署

| 检查点 | 问题 | 建议 |
|--------|------|------|
| 配置管理 | 配置如何管理？环境变量还是配置文件？ | 明确 |
| 热加载 | 策略配置是否支持热加载？ | 使用 viper 或类似方案 |
| 健康检查 | 服务是否提供健康检查接口？ | /health 端点 |

### 7. 测试

| 检查点 | 问题 | 建议 |
|--------|------|------|
| 单元测试 | 关键逻辑是否有单元测试？ | 目标覆盖率 X% |
| 表驱动测试 | 多场景用例是否使用表驱动？ | 推荐 |
| mock | 外部依赖是否使用 mock？ | 明确 |

## 输出格式

| 优先级 | 序号 | [Go]模块 | 问题描述 | 建议修改 |
|--------|------|----------|----------|----------|
| P1 | 1 | 并发 | 定时任务无 context 取消机制 | 使用 context.WithCancel |
| P1 | 2 | 内存 | 循环内使用 + 拼接字符串 | 改用 strings.Builder |
| P2 | 3 | 测试 | 关键逻辑无单元测试 | 补充表驱动测试 |
