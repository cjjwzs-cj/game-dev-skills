# Java 技术栈适配

## 适用场景
项目后端使用 Java 语言时，在审阅策划案和设计审查时追加以下检查点。

## 必查清单

### 1. JVM 内存

| 检查点 | 问题 | 建议 |
|--------|------|------|
| 堆内存 | 预估对象数量和大小，是否在堆内存范围内？ | 评估 + 配置 -Xmx |
| GC 压力 | 是否有大量短生命周期对象？ | 使用对象池或复用 |
| 内存泄漏 | 静态集合、ThreadLocal、未关闭资源 | 定期审查 |
| 本地内存 | DirectByteBuffer 是否及时回收？ | 明确 release 机制 |

### 2. 并发编程

| 检查点 | 问题 | 建议 |
|--------|------|------|
| 线程安全 | 共享变量是否有 volatile/synchronized/lock？ | 明确 |
| 线程池 | 是否使用自定义线程池？参数是否合理？ | 核心数、队列容量、拒绝策略 |
| 并发集合 | 是否使用 ConcurrentHashMap 而非 HashMap？ | 多线程环境必须 |
| CompletableFuture | 异步调用是否合理处理异常和超时？ | 明确 |
| 死锁预防 | 多个锁的获取顺序是否一致？ | 明确锁顺序 |

### 3. 数据库访问

| 检查点 | 问题 | 建议 |
|--------|------|------|
| 连接池 | HikariCP 配置是否合理？最大连接数？ | 明确 |
| N+1 查询 | JPA/Hibernate 是否有懒加载 N+1 问题？ | 使用 join fetch |
| 批量操作 | 是否使用 JDBC batch？| 明确 |
| 事务边界 | @Transactional 是否作用范围过大？ | 尽量小范围 |

### 4. 性能

| 检查点 | 问题 | 建议 |
|--------|------|------|
| 字符串拼接 | 循环内禁止使用 + 拼接 | 用 StringBuilder |
| 装箱拆箱 | 是否频繁发生 int→Integer 转换？ | 使用基本类型集合（如 IntList） |
| 热路径优化 | 高频调用是否避免创建新对象？ | 对象复用 |
| 缓存使用 | 热点数据是否使用本地缓存（Caffeine）？ | 明确 |

### 5. 日志与监控

| 检查点 | 问题 | 建议 |
|--------|------|------|
| 日志级别 | 生产环境日志级别？调试日志是否条件输出？ | 明确 |
| 日志框架 | 使用 Log4j2 还是 Logback？ | 明确 |
| 监控指标 | 是否暴露 metrics（Micrometer/Prometheus）？ | 明确 |
| 链路追踪 | 是否接入分布式追踪？ | 明确 |

### 6. 框架与规范

| 检查点 | 问题 | 建议 |
|--------|------|------|
| 框架选择 | Spring Boot/Netty/自研？版本？ | 明确 |
| 代码规范 | 是否遵循阿里巴巴/Google Java Style？ | 明确 |
| 空指针 | 是否使用 Optional 或 @Nullable 注解？ | 明确规范 |
| 异常处理 | 自定义异常 vs 标准异常？ | 明确层次结构 |

### 7. 游戏后端特有

| 检查点 | 问题 | 建议 |
|--------|------|------|
| Netty | 是否使用 Netty？Pipeline 配置？ | 明确 |
| Protobuf | 协议版本兼容性处理？ | 明确 optional |
| 热更新 | 策划配置是否支持热加载？ | 使用配置中心 |
| 定时任务 | 使用 Quartz 还是 @Scheduled？ | 明确，注意分布式问题 |

## 输出格式

### 标准输出格式

| 优先级 | 序号 | [Java]模块 | 问题描述 | 建议修改 |
|--------|------|------------|----------|----------|
| P1 | 1 | JVM | 活动对象无上限，可能导致 OOM | 增加对象数量上限 |
| P1 | 2 | 并发 | 使用 HashMap 而非 ConcurrentHashMap | 替换 |
| P2 | 3 | 性能 | 循环内使用 + 拼接字符串 | 改用 StringBuilder |

### 输出要求
- 按优先级排序：P0 → P1 → P2
- 每个问题必须包含：问题描述、建议修改
- 模块必须包含 `[Java]` 标签

### 无问题输出格式
如果未发现问题，输出：
```
✅ Java 技术栈适配检查通过，未发现明显问题

检查模块：
- ✅ JVM 内存
- ✅ 并发编程
- ✅ 数据库访问
- ✅ 性能
- ✅ 日志与监控
- ✅ 框架与规范
- ✅ 游戏后端特有
```

## 异常情况处理

| 异常情况 | 处理方式 |
|----------|----------|
| 策划案为空 | 输出错误："策划案内容为空，请提供有效的策划案内容" |
| 策划案格式异常 | 输出错误："策划案格式异常，请检查文件格式" |
| 技术栈不明确 | 输出警告："策划案未明确使用 Java 技术栈，检查结果可能不完整" |
| 审阅执行失败 | 输出错误："审阅执行失败，请检查策划案内容或联系技术支持" |

## 边界情况处理

### 策划案内容不完整
- **情况**：策划案只包含部分后端功能描述
- **处理**：基于现有内容审阅，输出警告提示可能遗漏的检查点

### Java 版本不明确
- **情况**：策划案未明确使用的 Java 版本（Java 8/11/17/21）
- **处理**：在问题描述中标注，建议明确 Java 版本，不同版本有不同的特性和性能特征

### 框架不明确
- **情况**：策划案未明确使用的框架（Spring Boot/Netty/自研）
- **处理**：在问题描述中标注，建议明确框架选择，不同框架有不同的最佳实践
