# Cocos Creator 技术栈适配

## 适用场景
项目前端使用 Cocos Creator 引擎时，在审阅策划案时追加以下检查点。

## 必查清单

### 1. 资源管理

| 检查点 | 问题 | 建议 |
|--------|------|------|
| 预制体加载 | 策划案中提到的预制体是否有动态加载计划？ | 明确哪些预制体需要动态加载 |
| Bundle 分包 | 是否考虑 Bundle 分包策略？首包大小？ | 明确分包方案（场景/资源/UI分包） |
| 图集管理 | 大量 UI 是否有图集规划？散图是否合并？ | 按模块合并图集，减少 draw call |
| 资源释放 | 场景切换时未使用的资源是否释放？ | 使用 assetManager.releaseAsset |
| 远程资源 | 热更新资源的下载和缓存策略？ | 明确 CDN + 本地缓存版本管理 |

### 2. 性能优化

| 检查点 | 问题 | 建议 |
|--------|------|------|
| 节点操作 | 是否有频繁的节点增删？是否使用对象池？ | 频繁使用的节点（子弹、特效）用对象池 |
| update 频率 | 是否有每帧更新的逻辑？涉及大量节点时是否降频？ | 减少 update 中的计算，或使用定时器 |
| 批量渲染 | 是否有大量 UI 同时显示？是否使用 Mask 或 Layout？ | 用滚动视图 + 复用节点 |
| draw call | 特效和 UI 的 draw call 是否可控？ | 合并图集，避免打断批处理 |
| 内存监控 | 长时间运行是否有内存增长？ | 定期检查未释放的资源 |

### 3. 跨平台发布

| 检查点 | 问题 | 建议 |
|--------|------|------|
| 小游戏平台 | 微信小游戏/抖音小游戏的适配方案？ | 明确平台判断和 API 封装 |
| iOS/Android | 原生平台的差异如何处理？ | 封装平台适配层 |
| 热更新 | 热更新方案？assetManager 还是自研？ | 明确热更流程和版本管理 |
| 启动速度 | 首场景加载时间？是否有 loading 优化？ | 分包加载 + 首场景精简 |

### 4. 代码组织（TypeScript 特有）

| 检查点 | 问题 | 建议 |
|--------|------|------|
| 全局事件 | 事件系统是单例 EventTarget？是否有事件销毁约定？ | 明确事件注册和反注册规范 |
| 装饰器使用 | 关键类是否使用 cc._decorator？ | 明确 @property、@ccclass 的使用 |
| 节点查找 | 是否大量使用 cc.find？是否影响性能？ | 用节点引用或路径缓存替代 |
| 模块化 | 代码是否按模块拆分？命名空间？ | 使用 ES6 模块或命名空间隔离 |

### 5. 游戏逻辑

| 检查点 | 问题 | 建议 |
|--------|------|------|
| 帧动画 | 动画播放的触发时机？是否支持网络同步？ | 明确动画状态机设计 |
| 触摸事件 | 触摸区域的判定逻辑？是否有点击穿透问题？ | 明确事件冒泡和阻止规则 |
| 摄像机 | 摄像机跟随逻辑？（大地图场景） | 明确边界限制 |

### 6. 调试与日志

| 检查点 | 问题 | 建议 |
|--------|------|------|
| 日志输出 | 生产环境是否关闭调试日志？ | 开关控制 |
| 性能分析 | 是否有性能分析开关（显示 FPS、draw call）？ | 内置或不内置，测试用 |

## 输出格式

| 优先级 | 序号 | [Cocos]模块 | 问题描述 | 建议修改 |
|--------|------|-------------|----------|----------|
| P1 | 1 | 资源 | Bundle 分包策略未定义 | 按场景/功能拆分 Bundle |
| P1 | 2 | 性能 | 频繁生成的子弹未用对象池 | 实现节点池 |
| P2 | 3 | 发布 | 微信小游戏适配方案未明确 | 封装平台 API |
